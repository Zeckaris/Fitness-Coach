# V9.5 — Exercise Library Rebuild & Media Integration: Changelog
 
**Status:** Shipped (with scope deviations from original scope doc — see below)
**Scope doc:** `V9.5 scope exercise library rebuild and media integration.md`
 
This changelog records what was actually built, where it diverged from
the pre-design scope, and which open items from the scope doc were
resolved. It does not replace the scope doc — that document still
reflects the original problem statement and design constraints and is
left as-is for historical reference.
 
---
 
## Summary
 
The exercise library (`data/workouts.json`) was rebuilt from the
[hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset),
as planned. Each entry carries real dataset-sourced media (`gif_url`,
`image`, `media_id`, `attribution`) alongside the project's existing
custom fields. Two things shipped beyond the original scope: the final
library is substantially larger than planned, and — despite being
explicitly called out as *not* committed to in the scope doc — the
Streamlit UI now renders the new media fields.
 
## Deviations from Scope
 
### 1. Exercise count: 89 shipped vs. ~40 scoped
 
The scope doc specified *"a smaller (~40 exercise), deliberately
curated set"* at roughly 3 per target area. The shipped library
(`workouts.json`, version 9.5) contains **89 exercises**
(`total_exercises: 89`) — more than double the planned count. The
per-target-area curation approach was evidently extended rather than
capped at ~3. Whether this was a deliberate expansion decision made
during design, or scope creep during authoring, is not captured in
either doc — worth a one-line note here once confirmed, so a future
version doesn't have to reverse-engineer the reason from the data.
 
### 2. Equipment vocabulary wider than documented
 
The scope doc's controlled vocabulary table lists the post-V9.5
`Equipment` set as: `none, dumbbells, bench, resistance_band,
kettlebell`. The shipped data includes at least one value outside that
set — `ab_wheel` (e.g. `abs_002`, "Band Assisted Wheel Rollerout") — and
the `search_workout_library` error trace from live usage shows
`pull_up_bar` also in use as an equipment value on at least one
back-exercise entry, neither of which appears in the scope doc's table.
**Action needed:** confirm the actual final `Equipment` `Literal` in
`tools/workout_library.py` and update the scope doc's table to match
reality, or treat this as a genuine V9.5 vocabulary expansion and
document it as such here.
 
### 3. Media UI rendering — explicitly out of scope, but shipped
 
The scope doc states: *"Any UI change to display the new gif_url/image
fields... not committed to or scoped here."* In practice,
`app/components/workout_session.py` now includes `get_exercise_media`,
`render_exercise_media`, and inline gif/image rendering during guided
workout sessions (with sizing and centering fixes applied post-launch).
This is a real, shipped feature this scope doc says wasn't planned —
effectively the "structured UI" version the scope doc mentions as
*"previously discussed... not committed to or scoped here"* arrived
bundled into V9.5 rather than as its own version.
 
## Open Items Resolved
 
- **Media field placement:** scope doc left open as *"flat on the
  exercise object vs. a nested `media: {...}` sub-object."* Resolved as
  **flat** — `gif_url`, `image`, `media_id`, and `attribution` all sit
  directly on each exercise record (confirmed against live
  `workouts.json`).
- **`RequiredSpace` semantic redefinition** (`minimal` → `indoor` /
  `outdoor`) shipped as documented in the scope doc's vocabulary table.
