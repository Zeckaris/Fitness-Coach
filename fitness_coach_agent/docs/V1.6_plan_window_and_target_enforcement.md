# V1.6 — Dynamic Planning Window, Target Dosing Guardrails, and Goal Exercise Scheduling

## Overview & Objectives

Following the V1.6.1 removal of 3-day blocks (replaced with week-level focus and per-day volume targets in `week_plans`), this spec defines the architecture and implementation plan for three critical planning fixes:

1. **Dynamic Planning Window (Today → Saturday):**
   - Eliminate hardcoded 3-day / 4-day fixed offsets (`(1, 2, 3)` from tomorrow).
   - Remove the prohibition against generating/updating plans for `today`.
   - Plan generation window dynamically targets **today through Saturday** (the remaining days of the current Sunday-anchored calendar week). Length varies from 7 days (on Sunday) down to 1 day (on Saturday).

2. **Schema-Level Target Guardrail (Deterministic Dosing):**
   - Address non-deterministic dosing where LLM outputs arbitrary reps/units (or omits `target_quantity`) for goal-tracked exercises.
   - Enforce schema/validation constraints requiring `target_quantity` and `unit` on goal-tracked exercises to match the date's exact `daily_target` from `daily_volume_targets`.

3. **Guaranteed Goal-Tracked Exercise Scheduling:**
   - Eliminate gaps where active volume-tracked exercises (e.g., *Squat to Overhead Reach*, *Skater Hops*) are left out of generated daily plans.
   - Require that goal-tracked exercises with daily volume targets are prioritized and scheduled into the generated session days.

---

## 1. Investigation Findings: Why Only 3 Days Were Generated

During testing on Wednesday, 2026-09-02, only 3 daily plans were generated (`2026-09-03`, `2026-09-04`, `2026-09-05`). 

**Root Cause Analysis:**
- `update_three_day_plan` and `_valid_plan_dates()` in `tools/plans.py` hardcoded the date offset tuple `(1, 2, 3)` relative to `today`.
- On Wednesday (`2026-09-02`), `today + 1` = Thursday (`09-03`), `today + 2` = Friday (`09-04`), and `today + 3` = Saturday (`09-05`).
- **Conclusion:** The generation of 3 days (Thursday–Saturday) was a coincidence of running on a Wednesday with a hardcoded `+1, +2, +3` relative offset. Today (`2026-09-02`) was explicitly excluded by validation guards, and on any day other than Wednesday, `(1, 2, 3)` would not align with Saturday.

## 2. Detailed Technical Requirements

### A. Dynamic Window (Today → Saturday)
- **Start Date:** Always `today` (`datetime.now(LOCAL_TZ).date()`).
- **End Date:** The upcoming Saturday of the current week (Sunday-anchored).
- **Validation:**
  - Remove error in `DayPlanInput` prohibiting `date == today`.
  - Accept any date between `today` and `saturday` (inclusive).
  - Update `update_three_day_plan` signature / description or replace with flexible multi-day update tool.
  - Update `generate_today_plan()` and `generate_backfill_days()` to construct a variable-length list of dates from `today` through `saturday`.

### B. Schema-Level Target Dosing Guardrail
- When `DayPlanInput` / `ExercisePlanItem` is validated, for any exercise in the `daily_volume_targets` for that date:
  - If the exercise is included in the plan, `target_quantity` MUST equal `daily_target` (or a multiple thereof if specified), and `unit` MUST match `unit`.
  - Pydantic models or validation functions will auto-fill or strictly validate `target_quantity` and `unit` against `get_daily_volume_targets_for_date(date)`.

### C. Goal-Tracked Exercise Coverage
- In `generate_today_plan()` and `BACKFILL_DAY_PLAN_PROMPT`:
  - Goal-tracked exercises with non-zero daily targets must be included in the candidate exercise pool.
  - LLM prompt instructions must explicitly mandate including all active goal-tracked exercises across the planned days in the window.

## 3. Proposed Implementation Phases

1. **Schema & Tool Updates (`tools/plans.py`):**
   - Update date calculation helpers to compute `[today ... saturday]`.
   - Update `DayPlanInput` model validators to allow `today` and validate `target_quantity` / `unit` against `daily_volume_targets`.
   - Generalize `update_three_day_plan` / `generate_today_plan` to handle variable-length date windows.

2. **LLM Prompt & Structured Output Updates (`agent/plan_generation.py`, `agent/prompts.py`):**
   - Update `BACKFILL_DAY_PLAN_PROMPT` to accept a dynamic list of dates (`days_to_plan`) rather than hardcoded 4 date fields.
   - Update `BackfillPlanOutput` schema to accept `1` to `7` days instead of forcing `len(days) == 4`.

3. **Coach Agent Tools & System Prompt Wiring (`agent/graph.py`, `agent/prompts.py`):**
   - Update Tool descriptions and system prompt guidance to reflect the dynamic `today -> Saturday` window.
