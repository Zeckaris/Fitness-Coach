# V1.6.2 — Periodized Week Theme Enums, Dynamic Dosing Matrix, and Backlog Integration

## Overview & Objectives

This specification defines the architecture for transforming **Week Themes** from static text labels into a **strict, periodized exercise science engine**. It pairs strict Theme Enums with a deterministic volume/dosing matrix and integrates with the Backlog system to guarantee fatigue management and varied, progressive workout programming.

---

## 1. Strict Week Theme Enums

To prevent the LLM from generating arbitrary, unstructured theme strings (e.g. `"Upper Body Blast"`), week themes are strictly typed using Pydantic Enums across all prompts, tool arguments, and database schemas:

```python
from typing import Literal

WeekThemeEnum = Literal["Foundation", "Volume", "Intensity", "Peak", "Deload"]
```

### Allowed Themes & Scientific Roles:
- **Foundation:** Balanced baseline work capacity (standard 1.00x volume, 3 sets, 65% intensity).
- **Volume (Accumulation Phase):** High set density and rep accumulation (1.15x volume, 4–5 sets, moderate intensity per set).
- **Intensity (Intensification Phase):** High effort per set with baseline volume (1.00x volume, 2–3 sets, 80–85% intensity per set).
- **Peak (Overreaching Phase):** Maximal volume and effort peak before recovery (1.25x volume, 4–5 sets, 80–85% intensity per set).
- **Deload (Realization / Recovery Phase):** Active recovery and fatigue dissipation (0.60x volume, 2 sets, 50% intensity per set).

## 2. Periodized Dosing & Volume Weight Matrix

### A. Volume Multiplier Matrix
When calculating `_calculate_week_targets()`, weekly volume targets are distributed across the month according to theme weights rather than flat 25% division:

$$\text{Week Volume Target} = \text{Month Target} \times \left( \frac{\text{Theme Weight}}{\sum \text{Theme Weights in Month}} \right)$$

| Theme Enum | Volume Weight | Default Sets | Rep Dosing Intensity | Example (for a 60-rep daily target) |
| :--- | :---: | :---: | :---: | :--- |
| **Foundation** | `1.00x` | 3 sets | Moderate (65% max) | **3 sets × 20 reps** (Standard baseline) |
| **Volume** | `1.15x` | **4 to 5 sets** | Moderate reps/set (60–65%) | **5 sets × 14 reps** (High set density) |
| **Intensity** | `1.00x` | **2 to 3 sets** | **High reps/set (80–85%)** | **2 sets × 30 reps** (Pushing single-set max) |
| **Peak** | `1.25x` | **4 to 5 sets** | **High reps/set (80–85%)** | **4 sets × 20 reps** (Max output) |
| **Deload** | `0.60x` | **2 sets** | Light reps/set (50%) | **2 sets × 10 reps** (Active recovery) |

### B. Dynamic Reps Calculation Formula
In `DayPlanInput` and `BackfillDayPlanInput` schema validators (`tools/plans.py`), reps per set are dynamically calculated from the session's target quantity and theme set count:

$$\text{reps\_per\_set} = \text{round}\left(\frac{\text{target\_quantity}}{\text{sets}}\right)$$

The UI renders `💪 Push-Up — {sets} sets x {reps_per_set} reps (target: {target_quantity} reps)`.

## 3. Backlog System Integration

### A. Volumetric Deficit Accounting
The backlog tracks incomplete work strictly by units owed, independent of the original theme:

$$\text{deficit} = \text{target\_quantity} - \text{completed\_quantity}$$

### B. Theme-Aware Reinsertion
When owed volume is folded into a future target date via `get_backlog()`, `target_quantity` increases by the deficit, and the target date's **Week Theme** shapes the new sets and reps:
- On a **Volume Day:** Extra reps expand the set count (e.g. 5 sets × 20 reps).
- On an **Intensity Day:** Extra reps expand the per-set rep count (e.g. 3 sets × 30 reps).

### C. Deload Safety Rule
System prompts enforce that backlog deficits MUST NOT be reinserted during a **Deload** week, protecting recovery and preventing overtraining.
